# Learn French with Aira

A comprehensible-input French learning web app: leveled content (CEFR A1–C2) plus daily streaks, taking a learner from zero French to native-level ("Pro").

## Commit workflow

- **Every commit is gated by Husky.** `.husky/pre-commit` runs `npm run verify` (format check → lint → dependency-tree check → security-audit check → generate Prisma client → push schema → seed → typecheck → unit tests → full production build) and refuses the commit if anything fails. `.husky/commit-msg` runs commitlint and refuses a commit message that isn't [Conventional Commits](https://www.conventionalcommits.org/) format.
- **`db:generate` must run before `typecheck` in both `verify` and CI — don't reorder this.** `src/generated/prisma` is gitignored, so a fresh checkout has no Prisma client on disk until it's generated; typecheck fails immediately without it (`Cannot find module '@/generated/prisma/client'`). This actually broke CI once (a leftover locally-generated client masked the bug until a real fresh-checkout run caught it) — see the 2026-09-09 M1 session summary entry below.
- **Write commit messages as `<type>(<scope>): <subject>`** — e.g. `feat(reader): add tap-to-translate`, `fix(streak): correct timezone bug`, `chore(deps): bump prisma`. Standard types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
- **If a change has no test covering it, write the test first**, then the change — don't commit code the pre-commit gate can't actually exercise.
- **`npm audit` is gated through `scripts/check-audit.mjs`, not called directly.** It fails on any high/critical vulnerability that isn't on the file's reviewed allowlist (currently: advisories inside Prisma CLI's own MySQL-introspection dev tooling, which this Postgres-only project never touches). A genuinely new vulnerability still blocks the commit. Don't "fix" a failing audit by raising the severity threshold or deleting the check — either resolve it for real or add a dated, reasoned entry to the allowlist.
- **The full gate is slow on purpose** (a production build runs on every commit) — that's the tradeoff Aira asked for in exchange for never pushing a broken build. Don't work around it with `--no-verify` unless Aira explicitly says to.
- **As of 2026-09-19, `DATABASE_URL` points at a real hosted Neon Postgres project, not the local `prisma dev` proxy** — see that date's session summary below. `npm run verify` pushes the schema, seeds data, and runs integration tests against whatever `DATABASE_URL` in `.env` points at (`ctx.db` in tRPC tests, real-DB integration tests by deliberate choice — mocking Prisma would mean the tests couldn't catch a bad schema or a broken query — keep doing this for new routers unless there's a specific reason not to). No local database process needs to be running any more for this to work; the several bullets below about the local `prisma dev` proxy's flakiness are kept for reference in case local dev ever falls back to it (no account needed, still works), but don't apply to the current Neon-backed setup — that flakiness was specific to the local proxy, not real Postgres.
- **[Local-`prisma dev`-fallback only] The local Prisma dev database must be running for a commit to succeed.** Since M1, `npm run verify` pushes the schema, seeds data, and runs integration tests against a real database (`ctx.db` in tRPC tests) rather than mocking it — run `npm run db:dev` in a separate terminal first.
- **[Local-`prisma dev`-fallback only] Don't assume the dev database is healthy just because `npx prisma dev ls` says `running`.** It has both stopped outright _and_ gone flaky-while-reportedly-running (`Connection terminated unexpectedly` / `ConnectionClosed` mid test-run, `ls` still says running) more than once in this environment — background processes here don't reliably persist or stay healthy across tool calls. Nothing is lost when the gate fails; git aborts the commit cleanly, so just fix and retry. If a commit fails with `ECONNREFUSED`, `ConnectionClosed`, or similar: don't bother with `npx prisma dev start aira-dev` (it has failed to actually revive a broken instance every time so far, even when it reports success) — go straight to tearing it down and rebuilding: `npx prisma dev rm aira-dev --force`, then `npx prisma dev --detach --name aira-dev`, then `prisma db push` + `npm run db:seed`, then re-run `npm run test` once standalone to confirm it's actually healthy _before_ retrying the commit (this wipes local data, which is fine — it's disposable dev data).
- **[Local-`prisma dev`-fallback only] Rebuild the DB and run `git commit` in the same Bash call, not two separate ones.** Confirming health with a standalone `npm run test` in one tool call, then committing in the next, has repeatedly passed the first and failed the second with the exact same `Connection terminated unexpectedly` — the daemon can die specifically in the gap _between_ tool calls, not just over wall-clock time. Chain rebuild → seed → `git commit` as one command so there's no gap for it to die in.
- **Vitest runs test files sequentially (`fileParallelism: false` in `vitest.config.ts`), not in parallel.** These are integration tests sharing one Postgres connection pool (Neon's pooler now, the local proxy's pool before 2026-09-19); running files concurrently corrupted Postgres's unnamed prepared-statement protocol across files on the local proxy. Not re-tested against Neon specifically — don't re-enable parallelism without confirming that first.
- **[Local-`prisma dev`-fallback only] `DATABASE_URL` needs `connection_limit=1` against the local `prisma dev` proxy — this isn't optional, and it's the same bug as the Vitest one above, just showing up in the live app instead of tests.** Discovered building M4: the home page fires 2-3 `useQuery` calls at once, tRPC batches them into one HTTP request, and the server resolves them concurrently — enough to corrupt the local proxy's prepared-statement protocol with the exact same `bind message supplies N parameters, but prepared statement requires 0` error. Real Postgres (CI's `postgres:16-alpine`, and Neon) doesn't have this limitation — this param is a local-proxy-only workaround. Re-add it if `DATABASE_URL` ever points back at the local proxy.
- **Never import `@/auth` (next-auth) at the top of a router file, or anything a router file statically imports.** `next-auth` requires the real Next.js runtime and breaks module resolution under Vitest — even just importing it (without calling it) is enough to break every test that imports `appRouter`. The session resolves `userId` once in `createTRPCContext()` (`src/server/api/trpc.ts`), which itself lazily `await import()`s `@/auth` inside `src/server/current-user.ts` rather than importing it statically. Procedures read `ctx.userId`; they never call `getCurrentUserId()` or touch `@/auth` directly. Tests construct their own `{ db, userId }` context and never go near any of this.
- **[Unconfirmed against Neon — was local-`prisma dev`-proxy-specific] Keep `Promise.all` in a tRPC procedure to 3 or fewer concurrent `ctx.db` calls.** Found building M4 against the local proxy: `progress.getDashboard` (4 queries in one `Promise.all`) failed every single time with `Connection terminated unexpectedly`, while `progress.recommendNextLesson` (3 queries, same shape) succeeded reliably. The fix was mechanical — sequential `await`s instead of `Promise.all` — and `getDashboard` hasn't been reverted to test whether Neon has the same limit. Keep following this rule for new procedures until someone actually tests a 4+ query `Promise.all` against Neon; don't assume it's fixed just because the underlying database changed.

## Project status

M0 (Project Foundations) is done except account-provisioning (Cloudflare R2, Sentry, PostHog) that only Aira can do — hosted Postgres and Vercel hosting are now both done (Neon and Vercel, see the 2026-09-19 session summaries). M1 (Content Model & Admin Panel) through M6 (Phase 2: Extend Upward) are all done or blocked-only, and M7 (Phase 3: Reach Pro) is mostly done — see [docs/TASKS.md](docs/TASKS.md) for the exact checklist. The full loop now works end to end: onboarding (`/onboarding`) → placement (`/placement`) → landed directly in a recommended lesson → reader at `/learn/[id]` (synced text, tap-to-translate, comprehension check, streak/level updates, offline-tolerant queueing, a B1+ speaking-practice prompt after finishing) → home (`/`) recommending the next lesson by level+interest+import-ownership → dashboard (`/dashboard`) with a daily-reminder opt-in, streak milestones at 7/30/100/365 days, and a "words to revisit" nudge → library (`/library`) for browsing off-path → import (`/import`, B2+ only) for pasting in your own article → an informal DELF/DALF-style self-check (`/level-check`). The whole app has been through a full responsive + accessibility + privacy pass and has real Playwright E2E coverage (`e2e/lesson-flow.spec.ts`), not just live-in-browser spot checks — though see the M7 session summary below for a currently-unresolved local environment issue with actually _running_ that suite. It's also now live at [learn-french-with-aira.vercel.app](https://learn-french-with-aira.vercel.app), auto-deploying from every push to `master`.

Four things are genuinely blocked, not just deferred: **real audio narration** (needs an actual human voice — mini-stories are written and seeded, but `audioUrl` stays null until someone records them, which also means the reader's audio-sync highlighting is implemented but unverified against real audio), **admin access control** (`/admin/*` and `/api/admin/upload` have zero auth right now — this is now a live public URL, not just solo local work, making this a real, currently-open gap, not a theoretical one), **real sign-in** (Google/Resend credentials exist as Vercel env vars from before this project connected Vercel, but `/signin` on the live site still says "not configured" — those values aren't actually functioning; needs checking directly in the Vercel dashboard, see the 2026-09-19 Vercel session summary), and **scheduled daily reminders** (Web Push subscription capture works and is tested, but actually sending on a schedule still needs a Vercel Cron job wired up — Vercel itself is connected now, this specific piece just isn't built). On local dev only (never in production — the fallback is hard-disabled there), progress is attributed to a single seeded local-dev user in place of real per-visitor sign-in. Analytics events are also recorded locally (`AnalyticsEvent` table) rather than in PostHog for the same account-provisioning reason. Three more things are blocked the same honest way as A1's audio narration: **real B2–C1 and C2 curated library content** (needs an actual author/licensor), **video/podcast import** (needs a transcription service), and **speech-to-text for speaking-activation** (evaluated in M7 — the only no-account option sends voice audio to Google with no data agreement, which conflicts with "private by default"; recording is record-and-playback only until there's a real contracted vendor). **The M5 soft-launch item stays explicitly not-ready**: don't invite real people until sign-in actually works and `/admin` has some access control — right now nobody could save progress, and anyone could vandalize the lesson library.

`AGENTS.md` at the repo root is Next.js's own framework-conventions file, regenerated by `next dev` — read it for Next.js-specific API/convention rules; it's separate from this file's project-specific guidance. `.agents/skills/` and `.windsurf/skills/` were added automatically by `prisma init` — official Prisma reference docs for AI coding agents; consult them (especially `prisma-cli` and `prisma-client-api`) before writing Prisma-related code.

  1. The reader (`/learn/[id]`) was fetching lessons via `lesson.getById`, which includes `ComprehensionQuestion.correctIndex` for the admin edit form — anyone could open devtools and read the quiz answer key before attempting it. Added `lesson.getForReader`, a `select`-scoped query that never includes `correctIndex`, and pointed the reader at it instead.
  2. `notifications.unsubscribe` deleted a push subscription by `endpoint` alone, with no check that the caller owned it — anyone who learned another user's endpoint string could delete their subscription. Fixed by scoping the delete to `endpoint` **and** `userId`.
  3. `resolveMediaPath` (local file storage, standing in for R2) checked path traversal with a naive `startsWith()`, which a sibling-directory name can defeat (e.g. `../secrets-evil` starts with `../secrets`). Fixed with a proper `path.relative()`-based containment check; confirmed the old check was a genuine miss by reverting to it and watching the new test fail.
- **Playwright E2E coverage** (`e2e/lesson-flow.spec.ts`, 3 new tests + the existing smoke test; `playwright.config.ts` now runs `fullyParallel: false` / `workers: 1` since all tests share the one local-dev-user fallback and one local DB connection): writing these — not just running them — caught three more real bugs:
  1. A failed word-save while offline never updated the visible "will sync once you're back online" banner, because that indicator only ever listened for failed lesson-completions, not failed word-saves. Fixed by threading an `onQueued` callback from `Reader.tsx` into `WordSpan.tsx`'s save-mutation error handler.
  2. "The next lesson" (and the reader's own lesson fetch) was non-deterministic — seed data created in the same batch can share a `createdAt` down to the millisecond. Fixed by adding an `id` tiebreaker to every `orderBy: { createdAt: ... }` in `lesson.ts` and `progress.ts` (5 call sites).
  3. ## Product method — don't design against this

The product's entire pedagogy is Krashen's **comprehensible input / i+1**: learners acquire French by reading and listening to material _slightly_ above their current level, not by drilling grammar or vocabulary out of context. Concretely:

- Content is not "correct/incorrect" graded exercises — it's leveled reading/listening material (stories, podcasts, news, native media) with lookup and comprehension support.
- Word lookup should never interrupt reading/listening flow (no modal dictionary detours) and should always **save the word** rather than just define it.
- Don't add flashcard/SRS drilling as a primary mechanic. Spaced review (V2) is a light, optional nudge back toward _re-encountering_ words in real content, not isolated drill.
- Reading and listening should be able to run in sync (text highlights with audio) wherever content has both.

## Domain vocabulary

| Term            | Meaning                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Level**       | CEFR scale A1–C2, matching French DELF/DALF exam levels. Every piece of content is tagged with one.                                              |
| **Pro**         | In-product branding for C2 — native-level, content chosen by interest not level.                                                                 |
| **i+1**         | Krashen's term for the target difficulty: just above the learner's current level.                                                                |
| **Known word**  | A word the learner has looked up or marked known; the running count is a core progress signal, tracked independently of "lessons completed."     |
| **Lesson**      | One unit of content (a mini-story, a podcast segment, a reading) with a comprehension check at the end. Completing one is what extends a streak. |
| **Streak**      | Consecutive calendar days (learner's local timezone) with at least one completed lesson. One freeze/week is earned to cover a missed day.        |
| **Mini-story**  | Short beginner (A1) content built from a small set of ~30–40 high-frequency words repeated across many scenes.                                   |
| **Import** (V2) | Learner-supplied content (article/video/podcast link) turned into an interactive lesson — B2+ only.                                              |

See [docs/PRD.md §6](docs/PRD.md#6-level-framework-a1--pro) for the full level → content-type mapping, and §5 for the method in more depth.

## Guardrails from the PRD

- **Non-goals (don't build unless asked):** live tutoring/conversation exchange, DELF/DALF certification as a first-class feature, native mobile apps, non-French languages.
- **Streak design:** the minimum unit that "counts" toward a streak must still deliver meaningful input — don't let it collapse into a trivial tap-through that games the streak without any exposure. See PRD §8 and the "streaks ≠ input" risk in §12.
- **Content rights:** library content must be licensed, public-domain, or produced in-house. Imported content (V2) is for the importing learner's personal study only — never redistributed to other learners.
- **Level estimates are directional**, not certified CEFR scores — don't present them to users as official.
- **Beginner cold-start:** A1 cannot be pure native input; it needs heavy scaffolding (bilingual text, transcripts, mini-stories) per the method itself. Don't simplify this away.

## Build order (per PRD §13)

1. **MVP:** A1–B1 content, synced reader/player, tap-to-translate + known-words tracker, streaks, progress dashboard, basic placement quiz.
2. **Phase 2:** B2–C1 content, bring-your-own-content import, interest-based recommendations, streak freeze/milestones.
3. **Phase 3 (Pro):** C2 native-media library, spaced word review, speaking-activation prompts.

Don't build Phase 2/3 features ahead of Phase 1 unless the user explicitly asks.
